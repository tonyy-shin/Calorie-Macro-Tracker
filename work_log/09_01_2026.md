## September 01, 2026 — Phase 2: USDA Silver Transform

**Nutrient ID selection**
- USDA's `usda_food_nutrient` has multiple candidate rows for both energy
  and protein per food, not just one - checked against the actual loaded
  data rather than assuming from USDA docs:
  - Energy: `1008` (KCAL, "Energy"), `1062` (KJ, wrong unit - excluded),
    `2047`/`2048` (Atwater General/Specific Factors - recalculated,
    would double-count against `1008` where both exist).
  - Protein: `1003` (Protein) vs `1053` (Adjusted Protein - nitrogen
    conversion factor adjustment, sparsely populated).
- Decision: went with `1008` (Energy, KCAL) and `1003` (Protein) -
  matches what's printed on a real nutrition label, easiest for users to
  recognize. Carbs (`1005`) and fat (`1004`) had only one candidate each.

**`usda_food_silver` build**
- Pivoted `usda_food_nutrient` from long format (one row per food+nutrient)
  to wide format (one row per food, kcal/protein_g/carbs_g/fat_g as
  columns) using `MAX(amount) FILTER (WHERE nutrient_id = '...')`
- `LEFT JOIN`ed `usda_food` (for `description`/name) with the pivoted
  nutrients and with `usda_branded_food` (for brand/barcode) - `LEFT
  JOIN` specifically because Foundation Foods (raw ingredients) have no
  branded-food row at all, and some foods may be missing nutrient data;
  `INNER JOIN` would have silently dropped those rows.
- `COALESCE(brand_owner, brand_name)` to pick whichever brand field is
  populated.
- All values cast `::DOUBLE PRECISION` at select time - first place
  bronze's all-TEXT data becomes real numbers.

**Result**
- `usda_food_silver` row count confirmed matching `usda_food` - clean
  pivot, nothing dropped in the joins.
- Performed SELECT * for usda_food_silver to see if it loaded properly.
