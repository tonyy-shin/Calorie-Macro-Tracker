**Key lessons learned**
- `\copy` is a `psql`-only client meta-command (not real SQL) — it reads files as the local OS user, which is why it works without special Postgres file permissions, unlike server-side `COPY`
- `\copy` always **appends**, never overwrites — it's insert-only with no dedup. Re-running the same load twice would duplicate rows. (Monthly full-reload strategy will need `TRUNCATE` or a staging-table swap to handle this deliberately, per the ingestion cadence design.)
- Bronze columns are all `TEXT` on purpose — lets ingestion succeed regardless of messy source data; all typing/validation is deferred to the silver layer
- Always verify a CSV's real header (`head -1 file.csv`) before writing `CREATE TABLE` — column counts/order can silently differ between files that look similar (caught this on `food_nutrient.csv`, which has an 11th column, `min_year_acquired`, not in the original plan)
- `\copy`'s column list must match the CSV header exactly — omitting it makes Postgres assume the file matches the table's own column order, which broke when `loaded_at` was in the middle of the table definition
- `microbe_data` (branded `food.csv`) loaded fine as raw text but is nested/structured data — will need its own parsing logic in the silver layer, not treated like the flatter columns
