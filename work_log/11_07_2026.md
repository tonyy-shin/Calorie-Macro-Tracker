# 11/07/2026 — Phase 7 (Streamlit app) + Phase 8 (daily OFF updates)

## Decision
- Dropped the FastAPI plan for Phase 7; built the app in Streamlit.

## Phase 7 — Streamlit app (`src/python/app.py`)
- Login gate (`verify_user` / `register_user`) with `user_id` in `st.session_state`.
- Pages: Home, Calendar, Logging, Create recipe, My recipes. Switched from
  `st.tabs` to a keyed radio because tabs reset to Home on every rerun.
- Food picker shared by Logging / Create recipe / editing: search, barcode
  (typed or camera via pyzbar), editable grams, remove, preview totals.
- Edit/delete logged meals from Home and Calendar (name, date, items or
  portions). Recipe meals scale their stored snapshot, so they stay
  editable even after the recipe changes or is deleted.
- Sidebar shows when food data was last updated (from `pipeline_runs`).
- DB credentials in `.streamlit/secrets.toml` (gitignored). Fixed a missing
  trailing newline in `.gitignore` that had glued two rules together.

## New backend modules (all with tests)
- `manual_foods.py`: `add_manual_food` (range checks, per 100 g). 25 checks.
- `app_queries.py`: `list_recipes`, `lookup_barcode` (matches UPC-A /
  EAN-13 / GTIN-14 zero-padded forms), `food_data_status`.
- `recipes.py`: `get_recipe`, `update_recipe`, `delete_recipe`; shared

- `meal_editing.py`: `get_meals_for_day`, `get_meal`, `update_meal`,
  `delete_meal`. 35 checks.
- `off_api.py`: live Open Food Facts lookup for one scanned barcode that

- `meal_logging.py`: `search_foods` now ranks own foods, complete macros,
  exact/prefix matches and shorter names first (plain "Banana" was buried
  under branded and macro-less rows). 4 new ranking checks.

## Phase 8 — daily Open Food Facts updates
- `src/python/off_pipeline.py`: applies every new daily delta (OFF keeps
  14 days), oldest first, one transaction per file; `--full` streams the
  full JSONL dump through the same SQL in batches. Advisory lock = one run
  at a time. Every run logged in `pipeline_runs`, with gap detection.
- SQL: `app/create_pipeline_runs.sql`, `gold/add_foods_source_off_tracking.sql`
  (unique barcode index + `source_modified_t`), `bronze/create_off_delta.sql`,
  `silver/create_off_delta_silver.sql`, `silver/null_off_delta_outliers.sql`,
  `silver/add_off_delta_calorie_check.sql`, `gold/upsert_off_delta.sql`.
- Upsert rules: update in place (ids never change; recipes and logged meals
  reference them), USDA rows never overwritten, older data never overwrites
  newer, unchanged rows not rewritten.
- `test_off_pipeline.py`: 35 checks with fake delta files.
- Scheduling: `deploy/systemd/off-update.service` + `.timer` (daily 07:15,
  `Persistent=true` catches up after sleep, retries on failure).
- Started the one-time `--full` refresh in the background (`off-full-refresh`).

## Bug found
- `silver/null_off_outliers.sql` was a copy of the USDA file, so OFF's
  impossible values (e.g. kcal > 900) were never nulled. Fixed; the full
  refresh corrects existing rows.

## Lessons
- Never run `gold/create_foods_source.sql` again: it drops the table and
  regenerates every id, breaking recipes and logged meals.
- Streamlit reruns the whole script on every click; anything that must
  survive goes in `st.session_state`, and widgets in a form only submit
  with the form's button.
- Barcodes for one product appear as 12, 13 or 14 digits depending on the
  source; match on zero-padded variants, not exact strings.
- OFF delta files only cover 14 days and don't record deletions.
