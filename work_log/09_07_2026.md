# 09/07/2026 — Phase 4: Manual Entries + Foods View

## Summary
Completed Phase 4: created the foods_manual table for user submitted
food entries and the foods view unifying foods_source and foods_manual
into a single queryable surface for the app.

## What was done
- Created `src/sql/gold/create_foods_manual.sql`
  - `CREATE TABLE IF NOT EXISTS foods_manual` 
  - `id` as identity PK, `user_id BIGINT NOT NULL REFERENCES users(id)`
  - Same macro shape as foods_source (barcode, name, brand, kcal,
    protein_g, carbs_g, fat_g), plus `created_at TIMESTAMPTZ DEFAULT now()`
- Created `src/sql/gold/create_foods_view.sql`
  - `DROP VIEW IF EXISTS foods` + `CREATE VIEW foods AS ...`
  - `foods_source UNION ALL foods_manual`, columns aligned
  - `origin` literal ('source'/'manual') and `NULL::BIGINT AS user_id`
    on the foods_source branch to match foods_manual's shape
- Verified: `SELECT origin, COUNT(*) FROM foods GROUP BY origin` returns
  4,723,063 under 'source', 0 under 'manual' (foods_manual empty) —
  matches foods_source row count exactly

## Bugs caught before running
- First draft of foods_manual made `id` a FK to users(id) instead of a
  separate identity PK + user_id FK — would've capped one food per user
- First draft of the view used CREATE TABLE + INSERT instead of
  CREATE VIEW — would've gone stale and duplicated data
- Second branch's SELECT list was misaligned with the
  view's column order — UNION ALL matches by position, not name
