## 2026-08-31 — OFF Bronze Full Load + Disk Resolution

**Goal:** Complete the full Open Food Facts bronze load 
(previously only a 1,000-row sample had succeeded).

**OFF full bronze load**
- Bug: the `\copy` column list used for the full load attempt was a
  guessed ~60-column list (typical OFF export shape), not the actual
  211-column `off_product` table schema. Postgres correctly rejected it
  with `extra data after last expected column` on the very first data row.
- Fix: generated the real column list programmatically from
  `information_schema.columns` (ordered by `ordinal_position`, excluding
  `loaded_at`) instead of hand-typing or guessing it. Wrote the full
  `\copy` command to a `.sql` file via heredoc and ran it with
  `psql -f`, rather than pasting 211 column names interactively.
- Load options: `FORMAT csv, DELIMITER E'\t', QUOTE E'\x01', HEADER true,
  ENCODING 'UTF8'` — same pattern proven on the earlier 1,000-row sample.
- Result: **4,535,553 rows** loaded into `off_product`. Verified against
  source file (`wc -l` = 4,535,554 lines, minus 1 header row) — exact
  match, confirming a clean load with nothing silently dropped.

**Status: Phase 1 (Bronze) is now fully complete for both sources.**
- USDA: `usda_food`, `usda_food_category`, `usda_food_nutrient`,
  `usda_nutrient`, `usda_branded_food` — all loaded.
- OFF: `off_product` — 4,535,553 rows loaded.

**Lesson learned:** Never hand-type or guess a long column list for
`\copy`. Pull it from `information_schema.columns` ordered by
`ordinal_position` every time — it's guaranteed to match the real table
and takes one query.
