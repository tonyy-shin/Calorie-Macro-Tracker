# 09/02/2026

## Phase 2 Silver — OFF transform + calorie check

### OFF silver transform
- Investigated `off_product` bronze schema via `information_schema.columns` —
  found OFF has no `_serving` duplicate fields, only
  `_100g` columns. Simpler reconciliation than expected.
- Chose `carbohydrates_100g` over `carbohydrates_total_100g`
  (2,213,367 vs 1,970 populated rows).
- Chose `brands` over `brands_en` (near-identical population, `brands`
  marginally more complete).
- `code` (barcode) has 60 duplicates across 4,535,553 rows — not
  unique enough to serve as identity column like USDA's `fdc_id`.
  Added `off_id BIGINT GENERATED ALWAYS AS IDENTITY` via `ALTER TABLE`
  after `CTAS` load.
- Built `off_product_silver`: regex guarded TEXT -> DOUBLE PRECISION casts
  (`^[0-9]*\.?[0-9]+$`) on kcal/protein/carbs/fat — OFF's user submitted
  TEXT is dirtier than USDA's, bare casts would fail the whole query on
  a single bad row. Only 1-3 bad values per column out of 4.5M.
- Verified row count matches bronze: 4,535,553 / 4,535,553.
- Caught and fixed a column-naming mismatch (`proteins_g` vs `protein_g`)
  that would have broken the gold-layer UNION ALL by name.

### Outlier nulling
- Range check revealed both sources had physically impossible values
  that passed the regex guard:
  - USDA: 6,019 bad kcal / 2,087,940 total (~0.29%)
  - OFF: 3,934 bad kcal / 4,535,553 total (~0.09%)
- Nulled out kcal > 900/100g and any macro > 100g/100g on both tables,
  per column to avoid nulling good columns alongside bad ones on the same row.
- Found negative carbs_g on USDA (min -0.705) — extended null-out to
  catch < 0 as well as > ceiling on all four columns, both tables.
- Verified: all mins ≥ 0, all maxes within bounds, zero rows over
  threshold on both tables.

### Calorie check
- Added `calorie_check BOOLEAN` to both silver tables.
- Logic: NULL if any of kcal/protein_g/carbs_g/fat_g is NULL,
  TRUE if |kcal - (protein*4 + carbs*4 + fat*9)| <= 20% of kcal, FALSE otherwise. 
- Results:
  - USDA: 1,706,601 TRUE (82%), 102,719 FALSE (5%), 278,620 NULL (13%)
  - OFF: 2,030,890 TRUE (45%), 162,456 FALSE (4%), 2,342,207 NULL (52%)
- FALSE rate consistent across sources (~4-5%) — suggests tolerance/
  formula calibrated reasonably rather than penalizing one source's
  data unfairly. OFF's much higher NULL rate reflects its underlying
  sparsity, not a flaw in the check itself.
